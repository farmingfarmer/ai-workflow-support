# Escalation routing — exact departments (not "Contracting/Legal" catch-alls)

Yesha's specific catch: the review showed "Contracting / X" five different ways — vague. Each finding type
should route to the **one exact group** that actually closes it. Below is a sensible default mapping for a
healthcare contracting shop; **confirm the real names and owners with Clint/Ellie** (Yesha: "break it down for
me — who are the actual groups, who do you go to"). Replace the right column with Keck's real team names.

| Finding type | Routes to (exact group) |
|---|---|
| IP ownership, license grant, indemnification, limitation of liability | **Contract Administration (Legal)** — closes these last |
| Business terms: scope, deliverables, pricing structure, limitation-of-liability business decision | **Business Owner** (requesting department) |
| PHI / HIPAA / BAA | **Privacy Office** |
| Data security, hosting, security review, incident response | **Information Security (InfoSec)** |
| Secondary data use / AI-model training on institutional data | **Privacy + InfoSec + Data Owner** (named steward) |
| Stark / anti-kickback / COI / physician relationships / Open Payments | **Compliance** |
| Insurance / certificates of coverage | **Risk Management** |
| Credentialing / licensure | **Medical Staff Office / Credentialing** |
| Sourcing, vendor selection, PO | **Procurement / Supply Chain** |
| Enterprise / precedent-setting / spend over threshold | **Executive Leadership (ELT) sign-off** |

**Agent change (v1.10 candidate):** in section 5 (Recommended Positions) and section 7 (Escalations), the owner
must be **one exact group from the confirmed list**, never a slashed catch-all. Until the list is confirmed, the
agent uses the defaults above and marks the owner "(confirm)".

**Why it matters for rollout:** Yesha's framing is that leaders reviewing contracts don't know what to say or who
to send things to; a precise owner per finding is exactly the "prescriptive, boom-boom-boom" guidance she wants the
tool to give them.
